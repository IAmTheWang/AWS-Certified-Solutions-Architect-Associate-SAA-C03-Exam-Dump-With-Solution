# Rust 为什么没有保洁阿姨：GC 人话版（短视频 · 约 4:01）

**一句话核心**：Go 靠"保洁阿姨"（GC）事后回收垃圾，换来省心，代价是内存膨胀、占 CPU、偶发停顿；Rust 靠所有权 + 编译器"魔鬼教官"让垃圾不落地，换来极致性能与稳定，代价是写代码时的心智负担。

**贯穿比喻**：内存 = 工作台；垃圾 = 葱皮、空碗；Go = 厨师 + 保洁阿姨；Rust = 机关弹簧 + 魔鬼教官。

## 分镜与口播

### 场景 1｜内存 = 工作台（0:00–0:35）
**画面**：工作台滑入 → 食材、锅碗瓢盆逐个落上台面（标注"变量""下载的数据"）→ 葱皮、空碗不断堆高，内存条飙红，"OOM 内存溢出"红章 + 屏幕震动 → 🐹 Go VS 🦀 Rust。

> 把电脑的内存，想象成一张工作台。你写程序产生的变量、下载的数据，就是台子上的食材、锅碗瓢盆，还有切剩下的菜叶子。
> 那什么是垃圾？切完洋葱留下的葱皮，用完不再碰的空碗。台子堆满了，新菜没地方放，电脑就会内存溢出，OOM，直接卡死。
> 懂了这一点，你就能看懂 GC 到底是什么，以及为什么 Rust 在性能上，能把 Go 甩开一大截。

### 场景 2｜Go：厨师 + 保洁阿姨（0:35–1:46）
**画面**：左上角出现"内存/CPU"仪表（贯穿全片）→ 厨师随手扔萝卜皮、把锅一推 → 阿姨拿放大镜盘查：萝卜皮扔进垃圾桶，牛肉连着炒锅留下 → 三张"代价"卡片：① 申请内存 1.5~3 倍 ② CPU 厨师 40% + GC 20~30% ③ 延迟曲线出现毛刺，阿姨拍肩让厨师停住，高频交易/游戏引擎/微秒级工具 = 事故。

### 场景 3｜Rust：机关弹簧 + 魔鬼教官（1:46–2:32）
**画面**：阿姨被 🚫 请出厨房，"垃圾根本就不应该落地" → 代码块 `{ … }` 的 `}` 高亮，暗门弹开，锅/碗/刀掉进洗碗槽（内存条始终很低）→ 魔鬼教官 👹 登场 → 借刀给二厨又切肉 ✋、沙拉端给客人还想抓花生米 🚫 → "编译通过 ✅ 才准点火 🔥"。

### 场景 4｜跑起来的差异（2:32–3:21）
**画面**：左 Go / 右 Rust 分屏，四张对比：① 少一层 GC 运行时 ② 1 GB vs 30 MB 条形图 ③ 毛刺曲线 vs 平滑直线 ④ 层层封装 vs 直接摸齿轮（内存对齐、SIMD），Linux 内核/浏览器内核/高频量化 → C·C++·Rust ✅。

### 场景 5｜那 Go 为什么没被淘汰（3:21–4:01）
**画面**：厨师喝咖啡"省心" vs "多花点电费" → 网络往返 50 ms 与 GC 暂停 0.5 ms 的条形图（放大镜都找不到）→ 半天上线 🚀 vs 三天三夜（报错计数器上涨）→ 天平：开发效率 vs 极致性能，"选 Go 还是 Rust？看你的场景"。

## 发布前请核对的几处表述

稿子里有几处说得偏满，动画里已把数字标成"示意"，但口播建议自己再斟酌：

- **"降维打击" / "牛这么多"**：Rust 在延迟敏感、内存敏感场景占优，但多数业务服务里 Go 的差距并不大。口播里我改成了"甩开一大截"，更保守的话可以说"在这类场景下优势明显"。
- **"1 GB vs 30 MB"、"20%~30% CPU"、"1.5~3 倍内存"**：属于典型/最坏情况的示意，不是通用数值（Go 默认 GOGC=100，堆峰值约为存活数据的 2 倍；GC 停顿通常在亚毫秒级）。
- **"Go 无法用于内核/浏览器内核"**：更准确是"这些场景主流选择是 C/C++/Rust"，口播已按此写法。
