# EP02｜收费站 vs 机场安检：ALB 和 API Gateway 为什么不合并

*系列：AWS 人话课 · 时长 3:00 · 来源：`notes/ALB-vs-API-Gateway-vs-Bastion-Host.md`*

**一句话核心**：ALB 是高速收费站，只管又快又便宜地分流；API Gateway 是机场安检，管鉴权、限流、计费，所以更慢更贵。两者常常串着用。

**贯穿比喻**：高速公路收费站 vs 机场安检与海关。

---

## 0:00–0:15 钩子

**画面**：左边一排车快速通过收费杆，右边旅客排长队过安检。

**口播**：
> 同样是 API 的大门，ALB 处理一千万次请求，大概只要几美分；API Gateway 却要三十多美元。价格差这么多，为什么 AWS 还要把它们做成两个服务，而不是合并？

## 0:15–1:05 ALB：收费站

**画面**：高速收费站，车牌识别抬杆；旁边小图标"心率监测仪"。

**口播**：
> 先说 ALB，它就是高速公路收费站。只看车牌，快速放行，延迟只有几毫秒。它背后接的是 EC2、容器这种真正能收请求的机器，按小时加一点点流量费。它还有个本事叫健康检查，像给每台服务器戴了心率监测仪，哪台连续几次没响应，就不再给它派流量。说白了，只要能提供 IP 和端口、能响应 HTTP，都能当它的后端：EC2、容器、一串 IP。想做灰度发布也是它的强项：新旧版本各一个目标组，权重设成九十比十，就能分流。为什么 AWS 不直接让大家用 Nginx？因为自建要租至少两台跨可用区的机器，自己做主备、换证书；ALB 买的是服务，不是机器。

## 1:05–1:50 API Gateway：机场安检

**画面**：安检口，查护照、测体温、限流、填表。

**口播**：
> 再说 API Gateway，它是机场安检加海关。查护照，就是校验 Token；测体温，就是防刷限流；还能给不同客户发不同的 API Key，设置每月几次的配额，超量直接弹回 429，请求根本打不到后端。它按请求次数收费，所以一千万次大约三十多美元。另外它还有个绝活：不需要任何服务器，直接把请求翻译成 AWS 的调用，比如写进 SQS 队列，或者写进 DynamoDB。还有，Lambda 本身没有网卡，也不监听 80、443 端口，API Gateway 站在公网，把 HTTP 请求翻译成 Lambda 能读懂的事件，再把结果包装成 HTTP 响应还给浏览器，等于一个协议翻译官。

## 1:50–2:25 为什么不合并

**画面**：收费站塞进一堆安检设备，车龙瞬间堵死，旁边写"延迟翻倍"。

**口播**：
> 那为什么不合并？三个原因。第一，性能矛盾。ALB 的使命是每秒扛几万请求，代码必须极致精简；你让它去解析 Token、算限流、改请求体，转发速度立刻就慢下来。第二，成本模型不同。ALB 便宜，是因为它不做这些事；API Gateway 卖的就是功能。第三，ALB 只是个纯粹的网络管道，不懂 AWS 内部的签名协议，所以必须接一个真正的服务；API Gateway 内置了翻译引擎，才能直连 AWS 服务。

## 2:25–2:45 实战：两个串起来

**画面**：流程图 用户 → API Gateway → ALB → ECS 容器。

**口播**：
> 所以大厂的经典架构，是两个一起上。用户先过 API Gateway 这道安检，校验 Token、防恶意刷量；通过之后，进入内网，由 ALB 把流量高速分发给后面成百上千个容器。一个管治理，一个管搬运，各干各的。

## 2:45–3:00 选择口诀 + 结尾

**画面**：两行口诀。

**口播**：
> 怎么选？要极致性能、高吞吐、低成本，用 ALB；要精细的 API 治理，或者搭配 Lambda 做无服务器，用 API Gateway。下期，我们看一个让人困惑的现象：S3 文件明明不存在，为什么返回 403？

## 讲之前核对（别讲错）

- "几美分 vs 三十多美元 / 一千万次请求"是笔记里的**粗略量级**，不是精确报价。口播保留"大概""大约"，并在画面加"以官网定价为准"。
- Lambda 也可以用 Function URL 或挂在 ALB 后面，**不是必须用 API Gateway**；视频里说的是"功能最完备的组合"。
- 延迟数字（ALB < 5ms，API Gateway 约 10–30ms）画面上不要放，口播只说"几毫秒"，避免被当成官方指标。
