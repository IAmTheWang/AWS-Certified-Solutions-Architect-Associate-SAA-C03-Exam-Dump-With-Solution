# EP09｜Docker、ECS、EC2、Fargate、Lambda：五个词谁管谁

*系列：AWS 人话课 · 时长 3:00 · 来源：`notes/ECS-vs-Docker-vs-EC2-vs-Lambda.md` 第一至五节*

**一句话核心**：Docker 负责把一个容器打包好，ECS 负责调度一堆容器；EC2 和 Fargate 是 ECS 的两种"底盘"；Lambda 是另一条路，事件来了才跑。

**贯穿比喻**：餐厅经理（ECS）管一批厨师（容器），每个厨师做同一道菜（同一个镜像）。

---

## 0:00–0:10 钩子

**画面**：五个图标乱成一团，中间一个问号。

**口播**：
> Docker、ECS、EC2、Fargate、Lambda，这五个词，新手最容易搞混：到底谁管谁？今天用一个餐厅经理的故事，三分钟理清。

## 0:10–0:55 Docker vs ECS

**画面**：一个餐盒（镜像）→ 一个厨师；很多厨师 + 经理。

**口播**：
> 先分清 Docker 和 ECS。Docker，负责把应用和运行环境，打包成一个镜像，再在一台机器上跑起来，这是一道菜和它的菜谱。ECS，是 AWS 提供的，帮你管理一堆容器的调度服务，这是餐厅经理。客人多了，经理临时叫更多厨师上岗；厨师请假，立刻补人；新菜谱发布，逐个替换，不让所有人同时下线；新客人来了，分给还没坐满的厨师。这套自动化，就叫容器编排。没有编排的话，容器多到几十上百个，这些事全靠人盯，根本忙不过来。

## 0:55–1:40 EC2 vs Fargate

**画面**：两种厨房：自己租的厨房 vs 看不见的云厨房。

**口播**：
> ECS 决定容器该在哪跑，而跑的地方，有两种答案。第一种，EC2 launch type：容器跑在你自己名下的 EC2 上，机器你建、补丁你打、扩缩容你管，等于自己租厨房，能 SSH 登进去。第二种，Fargate：跑在 AWS 完全托管、你看不见的计算资源上，你只需要声明要多少 CPU 和内存，其余黑盒，不出现在你的 EC2 列表里，也不能 SSH。一句话：ECS 是大脑，EC2 和 Fargate 是两种底盘，前者你自己管，后者 AWS 帮你管到看不见。账单也不同：前者按 EC2 计费，后者付的是按 CPU、内存和时长算的 Fargate 账单。

## 1:40–2:10 容器坏了怎么办

**画面**：厨师换人，而不是经理去厨房修厨师。

**口播**：
> 还有个思路要转变。容器不是一台完整机器，只是隔离的进程，坏了直接换新的，不是登进去修。要临时调试，用的是 ECS Exec，在容器里开个临时终端，不是 SSH，也不需要开 22 端口、维护密钥对。SSH 是远程登录 Linux 命令行的协议，默认 22 端口；Windows 对应的是 RDP，传的是整个桌面画面。它们的前提，是对方是一台有完整操作系统的机器，比如 EC2。

## 2:10–2:40 Lambda：随叫随到的临时工

**画面**：订单来了，临时工出现，做完走人。

**口播**：
> 那 Lambda 呢？它是随叫随到的临时工：某个事件发生，比如 S3 收到一张新图片，就跑一小段代码，跑完销毁，没人用就零花费。很多人以为 Lambda 的代码包放在 EC2 或 Fargate 上，其实不是，它存放在 AWS 内部的 S3 里，运行时才被取出来，丢进一个轻量的微型虚拟机里执行。

## 2:40–3:00 选型口诀 + 结尾

**画面**：四行选型表。

**口播**：
> 选型口诀：纯静态前端，S3 加 CloudFront；环境特殊、要常驻，EC2；Docker 化的 API，流量有波动，ECS 加 Fargate；偶发的短任务，Lambda。比如新做一个 Node 的后端 API，大概率走 ECS 加 Fargate，比自建 EC2 省心，也比 Lambda 更适合持续对外提供服务。下期，看发布新版本的三种姿势。
