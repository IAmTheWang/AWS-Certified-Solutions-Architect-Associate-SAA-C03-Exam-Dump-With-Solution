# EP03｜文件明明不存在，S3 为什么报 403？

*系列：AWS 人话课 · 时长 3:00 · 来源：`aws/route53-oac-403-vs-404-dns-cutover-real-case.md`*

**一句话核心**：S3 桶策略没给 `s3:ListBucket` 时，"文件不存在"会被统一伪装成 403，防止别人靠返回码猜出桶里有什么；OAC 则是只给某一个 CloudFront 发的专属工牌。

**贯穿比喻**：只对员工开放的大楼；CloudFront 是总前台；OAC 是前台的专属工牌；工号就是 distribution ID。

---

## 0:00–0:15 钩子

**画面**：浏览器输入一个不存在的页面，页面显示 `403 AccessDenied`，大红问号。

**口播**：
> 我打开一个根本不存在的页面，S3 却告诉我：403，没有权限，而不是 404，找不到。这不是 bug，是 AWS 故意的。这个坑我排查时踩过，三分钟讲给你。

## 0:15–1:00 规则：ListBucket 决定报什么错

**画面**：对照表。左：有 ListBucket → 404；右：没有 → 403。

**口播**：
> 先说规则。S3 判断请求，顺序是：先看你有没有权限，再看东西存不存在。如果你有 ListBucket 权限，也就是能翻目录，那文件不存在，它老实告诉你 404。但如果你只有读取单个文件的权限，没有 ListBucket，S3 就不告诉你到底是没权限，还是压根不存在，统一装死回 403。目的很明确：防止有人靠试文件名、看返回码，去猜桶里藏着什么。举个例子：你访问存在的首页，前台带着权限去取，成功；你访问一个拼错的文件名，S3 在没有 ListBucket 的情况下，不会告诉你不存在，只回 403。

## 1:00–1:50 OAC：大楼工牌

**画面**：一栋大楼，总前台戴着工牌，档案室门禁只认这个工号。

**口播**：
> 再说 OAC。想象一栋只对内部员工开放的大楼，这就是私有的 S3 桶，所有公开访问全部关闭。大楼门口有个总前台，就是 CloudFront，负责接待所有访客。但前台自己不是员工，进不了档案室。OAC，就是发给前台的专属工牌，工牌上印着工号，也就是这个 CloudFront 的 distribution ID。档案室门禁写死：只认这个工号。用户走正门，前台亮工牌，放行；有人绕过前台直接摸 S3 的域名，没工牌，拒绝。还有个细节：桶策略里要写清楚是哪一个 distribution。只写 CloudFront 这个服务，等于账号里任何一个 distribution 都能读这个私有桶；加上来源 ARN 的条件，才是只信任这一个具体实例。

## 1:50–2:20 为什么不干脆加 ListBucket

**画面**：给前台加了 ListBucket 后，前台手里多出一份完整文件清单，里面有"历史备份"几个字。

**口播**：
> 那为什么不干脆给前台加上 ListBucket，让报错更清楚？因为一旦给了，这个身份就能列出桶里所有文件名，包括从没链接过的历史备份文件。少给这一个权限，是 OAC 的标准最小权限设计：用调试麻烦一点，换不泄露文件清单。还有个连带的坑：CloudFront 里配的"404 返回首页"规则，因为 S3 永远不吐 404，其实是摆设。

## 2:20–2:45 排查别只看状态码

**画面**：两个 403 并排，一个标"S3 缺 ListBucket"，一个标"WAF IP 白名单"。

**口播**：
> 排查时还要小心：同样是 403，可能是这里的 S3 设计，也可能是 WAF 的 IP 白名单拦的。看起来一模一样，原因完全不同。别只盯状态码，要去看到底是哪一层挡的。顺便速记：401，是你没登录；403，我听懂了但拒绝，不解释；404，确实没有，我愿意告诉你实话。

## 2:45–3:00 考试速记 + 结尾

**画面**：一行字 `OAC → CloudFront securely accesses private S3`。

**口播**：
> 考试速记：看到"CloudFront 要安全访问私有 S3"，脑子里直接反应 OAC。它底层用 SigV4 签名，自动生效，选项里要你单独配置 SigV4 的，基本是干扰项。旧版叫 OAI，新项目用 OAC。下期讲 CloudFront 的总部为什么在美国。
