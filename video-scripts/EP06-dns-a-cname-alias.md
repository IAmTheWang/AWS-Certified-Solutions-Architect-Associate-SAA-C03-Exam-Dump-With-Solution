# EP06｜CNAME 还是 ALIAS？域名指向 CloudFront 的前台比喻

*系列：AWS 人话课 · 时长 3:00 · 来源：`aws/cfn-template-size-limit-region-waf-real-case.md` 第 8.11–8.14 节*

**一句话核心**：A 直接给地址，CNAME 让你再查一次，ALIAS 是 Route 53 替你查好；DNS 只管"店在哪"，到了店里的跳转和拒绝是 HTTP 层的事。

**贯穿比喻**：A = 写着房间号的名片；CNAME = 转接牌；ALIAS = 前台代办；DNS = 查号台；HTTP = 到店后和店员对话。

---

## 0:00–0:10 钩子

**画面**：一个域名 `example.com` 光秃秃，旁边一个"CNAME ✗"的红叉。

**口播**：
> 想让你的域名指向 CloudFront，该用 CNAME 还是 ALIAS？为什么裸域名上，CNAME 根本不能用？三分钟，一个前台比喻说清楚。

## 0:10–1:05 三种记录：名片、转接牌、前台代办

**画面**：前台场景，三个动画：递名片、指转接牌、前台自己去查。

**口播**：
> 你要找王老师，但他的工位老换。A 记录，是直接递给你一张写着房间号的名片，房间一换，名片就过期，得人手动改。CNAME，是前台给你一块转接牌，写着请去看另一块牌子，你要自己再走一步，才知道房间号。ALIAS，是前台替你代办：你问王老师在哪，前台自己去查最新位置，直接告诉你三零五。你完全不知道中间多了一步，看起来就像普通的 A 记录。它们对应的内容也不同：A 记录指向 IPv4 地址；AAAA 记录指向 IPv6 地址，四个 A，是因为 IPv6 地址是 IPv4 的四倍长；CNAME 指向另一个域名；ALIAS 指向某个 AWS 资源。

## 1:05–1:55 为什么裸域名不能设 CNAME

**画面**：裸域名牌子上挂着 NS、SOA、MX，一个 CNAME 想挤进去被推开。

**口播**：
> 那为什么 CNAME 不能用在裸域名上？规则是：一个名字上只要有 CNAME，就不能再有别的记录。而裸域名上必然有 NS、SOA 这些基础记录，所以冲突。ALIAS 是 Route 53 专门设计的，对外表现为 A 或 AAAA 记录，不违反规则，就能放在裸域名上。代价是：它只能指向 AWS 自家的资源，比如 CloudFront、ALB。前台只认识自家大楼里的人。顺便说 CNAME 的解析过程：先查你的域名，答案是它是另一个名字的别名；再去查那个名字，才拿到真正的 IP。好处是对方换 IP，你这边自动跟着变。

## 1:55–2:45 DNS 层 vs HTTP 层

**画面**：左边查号台打电话，右边到了店门口跟店员说话；店员指着隔壁说"请去那边"，浏览器地址栏跟着变。

**口播**：
> 再讲个容易混的。很多人以为，www 自动跳到不带 www，是 CNAME 或 ALIAS 干的。不是。整个访问分两个阶段。第一阶段，打电话问查号台，也就是 DNS，问店在哪条街，它只回答地址，说完就结束。第二阶段，走到店门口，和店员对话，这是 HTTP 层。店员可以说，本店搬了，请去隔壁，这就是 301 跳转，浏览器地址栏才会变。DNS 记录，没有能力改你地址栏里的网址。把整条链路串起来：先问 Route 53 要地址；再走到 CloudFront 门口，保安 WAF 查你是谁，迎宾员 Function 看一眼改个路；最后回源拿页面。Route 53 只出现在第一步，其余都是 HTTP 层。

## 2:45–3:00 考点 + 结尾

**画面**：两条要点。

**口播**：
> 考点记两条：Route 53 的 ALIAS 能用在裸域名上，只能指向 AWS 资源；跳转是 HTTP 层的事，不是 DNS 的事。下期，我们讲 CloudFormation，为什么要像宜家一样看说明书。
