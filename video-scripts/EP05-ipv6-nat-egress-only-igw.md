# EP05｜IPv6 为什么需要一道"单向旋转门"？

*系列：AWS 人话课 · 时长 3:00 · 来源：`aws/cfn-template-size-limit-region-waf-real-case.md` 第 8 节*

**一句话核心**：IPv4 靠 NAT"总机"天然挡住外部来电；IPv6 地址本身公网可达，没有总机，要想"只出不进"，就得用 Egress-only Internet Gateway。

**贯穿比喻**：IPv4 = 8 位电话号码；NAT = 公司总机；IPv6 = 给每粒沙子一个号码；Egress-only IGW = 地铁出站单向旋转门。

---

## 0:00–0:15 钩子

**画面**：一排沙子，每粒沙上贴一个电话号码标签。

**口播**：
> IPv4 的地址快用光了，IPv6 的地址多到，可以给每一粒沙子都分一个。但你知道吗，IPv6 的服务器，反而更需要一道单向旋转门。为什么？

## 0:15–0:50 两种号码

**画面**：8 位号码 vs 20 位号码，老电话拨不通。

**口播**：
> 先把两个概念摆正。IPv4 像八位电话号码，大约四十三亿个，不够用了。IPv6 是又长又多的新号码，每个设备都能有自己的公网地址。关键是，老电话打不通新号码，两者不能直接互通，所以现实里是双栈：同一个网站，原来只有一个正门，也就是 IPv4，开了 IPv6，是再加一个侧门，两个门都能进。IPv6 不是 IPv4 的替代品，现实中会长期并存。

## 0:50–1:35 NAT：公司总机

**画面**：公司总机，员工分机号，外面只看到一个总机号码。

**口播**：
> 再说 NAT，网络地址转换，你可以把它理解成公司总机。公司只有一个对外号码，每个员工是内部分机。员工往外打，总机替你拨；外面回电，总机转给分机。外界永远看不到分机。这就带来一个副作用，也是好处：外部没法主动打给某个分机，天然做到了内部能出去，外部进不来。顺带说它的邻居 DHCP，像酒店前台：你一入住，自动发房卡，也就是 IP 地址，退房就收回。电脑连上 Wi-Fi 自动拿到 IP，靠的就是它。

## 1:35–2:05 IPv6：没有总机

**画面**：IPv6 设备直接暴露在公网，旁边装上单向旋转门。

**口播**：
> 问题来了：IPv6 的地址本身就是公网可路由的，不需要转换成总机号码，也就没有总机帮你藏起来。要是直接接普通的互联网网关，外面就能主动连进来。所以 AWS 提供了 Egress-only Internet Gateway，像地铁出站口的单向旋转门，只能出，不能进。内部能主动访问外部，外部没法主动连进来。

## 2:05–2:25 一张表 + 一个更正

**画面**：两行对照表。

**口播**：
> 总结成一张表：私有子网里的 IPv4 服务器要访问外网，用 NAT Gateway；私有子网里的 IPv6 服务器，要出网又不让外面连进来，用 Egress-only Internet Gateway。补充一句，别说得太绝对：NAT Gateway 的核心是 IPv4 转换，但后来也加了 NAT64 模式，让只有 IPv6 的机器访问 IPv4 的服务。

## 2:25–3:00 实战坑 + 结尾

**画面**：白名单上只写了一行 `::1/128`，所有来访者被挡在门外。

**口播**：
> 最后一个实战坑：给网站做 IP 白名单，要把 IPv4 和 IPv6 都写上。IPv6 默认值写的是 ::1，那是本机自己，等于访客名单上只写了我自己，真正来的人，全被挡在门外。还有一个发现：CloudFront 打开 IPv6 开关，只说明它有能力接待；访客要真走 IPv6，域名上还得有 AAAA 记录。开关打开，不等于真有流量走这条路，要用 DNS 查一下最终链路。下期讲域名怎么指向 CloudFront。
